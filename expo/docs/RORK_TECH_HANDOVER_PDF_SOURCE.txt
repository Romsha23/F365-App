1. Executive Summary
F365 Advanced is a cross-platform Expo / React Native health and fertility app built in Rork. It runs on iOS, Android, and web through Expo Router and React Native Web. The current stack combines a React Native frontend, Supabase authentication/database, Hono + tRPC backend routes, Rork toolkit services, Mixpanel analytics, Stripe hosted checkout, Expo notifications, and fertility/AI modules.

4. Country Access and Feature Gating
The app should not use separate admin UIs for feature control. Admin control is handled externally through the country_feature_flags and country_access tables.

country_access:
Purpose: block/allow complete app access by country.
Current app behavior:
- Pre-login: app checks detected device country in app/_layout.tsx through utils/country-access.ts
- Post-login: app checks the user's profile country after session restore
- No row means allowed
- Row with is_enabled=false means blocked and shows CountryBlockedScreen

country_feature_flags:
Purpose: enable/disable app features per country and access tier.
Current app behavior:
- Feature keys are defined in constants/feature-keys.ts
- FeatureGate component can grey out or block disabled features
- Admin dashboard manages rows externally
- No separate mobile admin UI should be built

Recommended feature rows:
- AU / fertility_pathway / enabled true
- AU / cost_estimator / enabled true
- AU / ivf_roadmap / enabled true
- AU / doctor_questions / enabled true
- IN, PK, US, UK rows as needed by rollout policy

6. Authentication
Provider: Supabase Auth.
Supported flow:
- App launch restores Supabase session with timeout
- If session exists, fetch users row by auth_id
- If onboarded, route to /(tabs)
- If not onboarded, route to /onboarding
- If no session, show /login
- Logout calls Supabase signOut and clears local state

Important file areas:
- app/_layout.tsx: restore session and routing
- app/login.tsx: email/password login
- app/onboarding.tsx: registration/profile collection
- app/reset-password.tsx: password reset
- store/user-store.ts: user profile and auth-related state

Known consideration: demo mode can create local-only user state. Server/database writes must handle missing Supabase auth gracefully.

11. AWS / Future Scaling Migration
Likely AWS target architecture:
- Frontend: Expo app stays as-is
- API: Hono/tRPC deployed to Lambda + API Gateway, or ECS if long-running server preferred
- Database: Supabase Postgres migrated to RDS PostgreSQL or Aurora Serverless
- Auth: Supabase Auth migrated to Amazon Cognito
- Secrets: AWS Secrets Manager and SSM Parameter Store
- Encryption: KMS, RDS encryption, server-side AES-256-GCM for sensitive data
- Logs: CloudWatch structured logs
- Audit archive: S3 with lifecycle/retention policies
- Push: SNS plus FCM/APNs if server-side push is required
- WAF/Rate limit: AWS WAF + API Gateway throttling

Migration priority:
1. Move hardcoded secrets/tokens to env/config where applicable
2. Add backend auth middleware and server-side authorization
3. Build Stripe webhook handler
4. Verify delete/export covers all user tables
5. Migrate database schema/data using pg_dump/pg_restore style process
6. Replace Supabase Auth with Cognito if AWS-only target is required
7. Replace direct Supabase client writes with API-layer writes
8. Add monitoring, rate limiting, audit persistence, test coverage
