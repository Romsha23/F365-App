## Implementation Details

### 1. User Consent Gate

**File:** `app/consent.tsx`  
**Status:** ✅ Fully Implemented  
**Compliance:** HIPAA, GDPR

#### Purpose
Obtain explicit, informed consent before any AI processing of health data. Users must actively opt-in to AI features.

#### Features
- **Granular consent options:**
  - Data Processing (Required for core services)
  - AI Processing (Required for AI features)
  - Anonymous Analytics (Optional)
  - Marketing Communications (Optional)
  - Research Participation (Optional)

- **Consent tracking:**
  - Timestamp of consent (`aiConsentDate`)
  - Consent type and scope
  - Audit logging of consent events

- **User controls:**
  - Ability to revoke consent at any time
  - Clear explanation of what each consent covers
  - Link to full privacy policy

#### Implementation
```typescript
// Consent is checked before AI features are accessible
const { user, updateUser } = useUserStore();

// AI features are disabled if consent not given
if (!user?.aiProcessingConsent) {
  // Show consent prompt or disable feature
}

// Audit logging on consent changes
logConsentGiven(user?.uniqueId, 'ai_processing');
logConsentRevoked(user?.uniqueId, 'ai_processing');
```

#### Validation
- ✅ AI features require `aiProcessingConsent: true`
- ✅ Consent state persists across sessions
- ✅ All consent changes are audit logged
- ✅ HIPAA compliance statement included

### 2. Disclaimer Banners

**File:** `components/DisclaimerBanner.tsx`  
**Status:** ✅ Fully Implemented  
**Compliance:** Medical liability protection

#### Purpose
Ensure users understand that AI-generated insights are not medical advice, diagnosis, or treatment.

#### Components

##### Master Disclaimer
```typescript
const MASTER_DISCLAIMER = "F365 provides wellness insights based on patterns in your self-reported data. These insights are not medical advice, diagnosis, or treatment. Predictions reflect trends, not certainties."
```

##### Specialized Disclaimers
- **Prediction:** "Predictions are based on recent patterns and may change"
- **AI Explanation:** "This explanation is informational, not medical diagnosis"
- **Correlation:** "Charts show correlations, not cause-and-effect relationships"
- **Export:** "Generated by F365 using user-reported data. Not for clinical decision-making"
- **Crisis:** "If you're feeling unsafe, contact local emergency services"
- **Consent:** "I understand that F365 provides wellness insights, not medical advice"

##### Banner Types
1. **DisclaimerBanner** - Inline banners (info, warning, correlation)
2. **PredictionDisclaimer** - Interactive "How predictions work" modal
3. **AIExplanationFooter** - Footer for AI-generated content
4. **ExportDisclaimerFooter** - Footer for exported data
5. **ConsentCheckbox** - Consent acknowledgment UI

#### Usage Examples
```typescript
// Prediction page
<PredictionDisclaimer style={styles.disclaimer} />

// AI insights page
<DisclaimerBanner 
  type="info" 
  message={DISCLAIMERS.aiExplanation}
  dismissible={false}
/>

// Correlation charts

  type="correlation" 
  message={DISCLAIMERS.correlation}
/>

// After AI response
<AIExplanationFooter />
```

#### Validation
- ✅ Disclaimers present on all AI feature pages
- ✅ Non-dismissible disclaimers for critical information
- ✅ Clear visual hierarchy (icons, colors)
- ✅ Accessible and mobile-friendly

### 3. Confidence Badges

**File:** `components/ConfidenceBadge.tsx`  
**Status:** ✅ Fully Implemented  
**Compliance:** Transparency requirements

#### Purpose
Provide transparency about the reliability of AI predictions based on available data quantity and pattern consistency.

#### Confidence Levels

| Level | Criteria | Display | Color |
|-------|----------|---------|-------|
| **High** | 30+ data points, consistent patterns | "High confidence" | Green |
| **Medium** | 14-29 data points, emerging patterns | "Medium confidence" | Gold |
| **Low** | 3-13 data points, building baseline | "Still learning your baseline" | Primary Blue |
| **Learning** | 3-13 data points | "Still learning your baseline (X/14 days)" | Secondary |
| **Insufficient** | <3 data points | "Not enough data yet" | Muted Gray |

#### Components
1. **ConfidenceBadge** - Standard badge with optional description
2. **ConfidenceIndicator** - Full indicator with progress bar
3. **calculateConfidenceLevel()** - Helper function for level calculation

#### Implementation
```typescript
// Calculate confidence based on data points
const confidenceLevel = calculateConfidenceLevel(dataPoints, 3, 14, 30);

// Display badge
<ConfidenceBadge 
  level={confidenceLevel}
  dataPoints={dataPoints}
  minDataPoints={14}
  showDescription={true}
/>

// Compact indicator
<ConfidenceIndicator 
  confidence={0.85}
  dataPoints={dataPoints}
  showLabel={true}
  compact={true}
/>
```

#### Validation
- ✅ All predictions show confidence level
- ✅ Clear explanation of what confidence means
- ✅ Visual progress indicator
- ✅ Encourages more data logging for better predictions

### 5. Audit Logging

**File:** `utils/audit-logger.ts`  
**Status:** ✅ Fully Implemented  
**Compliance:** HIPAA, GDPR audit requirements

#### Purpose
Maintain a complete, tamper-evident audit trail of all AI interactions and data access for compliance and security.

#### Logged Actions
- `login` - User authentication
- `logout` - Session termination
- `data_access` - Reading health data
- `data_create` - Creating new records
- `data_update` - Modifying existing records
- `data_delete` - Deleting records
- `export_data` - Data export requests
- `settings_change` - Configuration changes
- `password_change` - Security changes
- `consent_given` - Consent granted
- `consent_revoked` - Consent withdrawn

#### Log Entry Structure
```typescript
type AuditLogEntry = {
  timestamp: string;           // ISO 8601 format
  userUniqueId: string;         // Anonymized user identifier
  action: AuditAction;          // Action type
  details: string;              // Sanitized details
  ipAddress?: string;           // Network information
  deviceInfo?: string;          // Device metadata
};
```

#### Helper Functions
```typescript
// Data operations
logDataAccess(userUniqueId, 'cycle_data', dataId);
logDataCreate(userUniqueId, 'log_entry', dataId);
logDataUpdate(userUniqueId, 'user_profile');
logDataDelete(userUniqueId, 'log_entry', dataId);

// Authentication
logLogin(userUniqueId);
logLogout(userUniqueId);

// Consent
logConsentGiven(userUniqueId, 'ai_processing');
logConsentRevoked(userUniqueId, 'data_processing');

// Other
logExportData(userUniqueId, 'CSV');
logSettingsChange(userUniqueId, 'notification_preferences');
```

#### Features
- **Anonymization:** PII is sanitized before logging
- **Local storage:** Max 1000 entries locally
- **Server sync:** Periodic sync with secure server (production)
- **User access:** Users can view their own audit logs
- **Retention:** Logs retained per compliance requirements

### 6. RLS Policies (Database)

**Location:** Supabase Database  
**Status:** ✅ Implemented  
**Compliance:** HIPAA data isolation

#### Purpose
Ensure users can only access their own health data at the database level, preventing data leaks even if application logic fails.

#### Policies
```sql
-- Users can only read their own data
CREATE POLICY "Users can view own data" ON cycle_logs
  FOR SELECT USING (auth.uid() = user_id);

-- Users can only insert their own data
CREATE POLICY "Users can insert own data" ON cycle_logs
  FOR INSERT WITH CHECK (auth.uid() = user_id);

-- Users can only update their own data
CREATE POLICY "Users can update own data" ON cycle_logs
  FOR UPDATE USING (auth.uid() = user_id);

-- Users can only delete their own data
CREATE POLICY "Users can delete own data" ON cycle_logs
  FOR DELETE USING (auth.uid() = user_id);
```

#### Coverage
- ✅ cycle_logs
- ✅ user_profiles
- ✅ ai_interactions
- ✅ audit_logs
- ✅ All user-specific tables

#### Validation
- Database-level enforcement
- No cross-user data leaks possible
- Tested with multiple user scenarios
