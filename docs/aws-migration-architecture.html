F365 — Hybrid AWS + Supabase Architecture

Front-end web, marketing site, email and operational workloads run on AWS. Application database, auth and Edge Functions remain on Supabase. This document is the canonical reference for the migration.

2. Component Responsibilities

AWS

Edge & API

  • CloudFront + WAF + ACM — global CDN, TLS, OWASP rules.
  • API Gateway — public REST endpoints; JWT auth via Cognito (admin) or Supabase (app).
  • Lambda — Stripe webhooks, email orchestration, scheduled reports, ops.
AWS

Web Hosting

  • Amplify Hosting / S3 + CloudFront — marketing site & admin dashboard.
  • Route 53 — DNS for app, www, api, admin.
  • S3 — exports, backup snapshots, static assets.
AWS

Email & Messaging

  • SES — transactional + drip emails, DKIM, SPF, DMARC.
  • EventBridge — cron schedules for digests/reminders.
  • SQS / SNS — async queues, retries, fan-out to email/push.
AWS

Security & Ops

  • Cognito — staff SSO for admin tools.
  • Secrets Manager + KMS — Supabase service key, Stripe key, OpenAI key.
  • CloudWatch — logs, metrics, alarms; Sentry for crash.
Supabase

Data Plane (kept)

  • Postgres with RLS — application database (users, cycles, IVF, etc.).
  • Auth — mobile app users (email, OTP, social).
  • Edge Functions — AI chat, fertility predictions, realtime triggers.
  • Storage — user-uploaded media.
3rd Party

External Integrations

  • Stripe — web checkout & invoicing; webhook → Lambda → Supabase.
  • RevenueCat — iOS/Android subscriptions; webhook → Lambda.
  • OpenAI — called from Supabase Edge Functions.
  • Mixpanel · Sentry · APNs/FCM.

4. Key Data Flows

App → Data

Mobile app authenticates with Supabase Auth, reads/writes Postgres directly with RLS, and invokes Supabase Edge Functions for AI features.

Stripe / RevenueCat → Entitlements

Provider posts webhook → CloudFront → API Gateway → Lambda verifies signature → writes entitlement row in Supabase via service key (in Secrets Manager).

Email Lifecycle

EventBridge cron / Supabase trigger → SQS → Lambda renders template → SES sends → bounce/complaint topic → CloudWatch alarm.

Admin Dashboard

Staff sign in to Cognito (MFA) → Amplify-hosted SPA → API Gateway (Cognito authorizer) → Lambda → read-only views of Supabase + ops actions.

6. Security Controls

Identity

  • Supabase Auth for end users; Cognito for staff with MFA.
  • Least-privilege IAM roles per Lambda; no long-lived keys.

Data

  • Postgres RLS enforced for every user-scoped table.
  • S3 buckets private + SSE-KMS; signed URLs for downloads.
  • Daily PITR snapshots replicated to S3 (cross-region).

Edge

  • WAF managed rule sets, rate limiting, geo controls.
  • ACM TLS 1.2+; HSTS on web origins.

Secrets

  • Secrets Manager with KMS CMKs; auto-rotation where supported.
  • No secrets in client bundles or repo.

8. Risks & Mitigations

Cross-cloud latency

Lambdas in same region as Supabase project; cache reads in CloudFront where safe.

Secret sprawl

Single source: AWS Secrets Manager; Supabase uses Vault for its own keys only.

Webhook replay / loss

API Gateway → SQS → Lambda with idempotency keys and DLQ.

Email deliverability

Warm SES domain, monitor bounces < 5%, complaints < 0.1%.
